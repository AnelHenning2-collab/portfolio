SQL · LEAVER TEST
-- terminated staff disabled late or not at all
SELECT r.employee_id, r.termination_date,
       a.status, a.disabled_date,
       days_to_disable
FROM staff_roster r
LEFT JOIN ehr_accounts a
  ON a.employee_id = r.employee_id
WHERE r.status = 'Terminated'
  AND (a.status = 'Active'
   OR days_to_disable > 1);

('E-1017', '2026-04-08', 'Disabled',
 '2026-04-27', 19)
SQL · MFA TEST
-- active accounts with no MFA,
-- including shared and vendor
SELECT account, account_type,
       mfa_enabled
FROM ehr_accounts
WHERE status = 'Active'
  AND mfa_enabled <> 'Yes'
ORDER BY account_type;

('FRONTDESK', 'Shared',  'No')
('e1008',     'User',    'No')
('e1022',     'User',    'No')
('VENDOR-IT', 'Vendor',  'No')
days_to_disable is computed with julianday(disabled_date) − julianday(termination_date). Output contains account IDs only — no ePHI, passwords or keys.

GUIDE

How to Use This Package

Seven steps that take a small practice from naming an owner to a program that improves every cycle.
1
Start with governance
Name a security official and an owner for each risk.
↓
2
Run the risk register
List systems that hold ePHI, score each risk, choose a treatment, and assign an owner and due date.
↓
3
Document controls
Use the control narratives to record how each control works and what evidence proves it.
↓
4
Collect evidence the safe way
Minimum necessary information, redact when possible, restrict access, and store in an approved repository.
↓
5
Test and monitor
Run the access-control script each month and review logs weekly; record any exception in the tracker.
↓
6
Report to leadership
Use the governance report to show posture, findings and the decisions needed.
↓
7
Repeat
Review the program on a schedule so it improves each cycle.
